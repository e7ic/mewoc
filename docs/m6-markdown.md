# M6 第六批：Markdown 导入与导出

## 实施前白盒模型

继续 React 17、JavaScript / JSX、Tiptap 3、Zustand、AntD 5、Rsbuild 1、Node 18.18+，M5 保持暂缓。Markdown 是有明确转换范围的交换格式，完整可编辑备份仍用 Mewoc 文件。

- 按需加载 unified 11、remark-parse / stringify 11、remark-gfm 4、remark-math 6，直接在 MDAST 与既有 Tiptap JSON 之间转换。解析与序列化交给库，不自行用正则实现 Markdown，也不经 HTML 中转。
- 导入由独立 AntD 弹窗拥有源码、标题、文件读取/转换状态、转换结果和错误。支持选择 UTF-8 .md / .markdown 文件及粘贴源码；先查看转换结果与说明，再新建文档。复用 FileActions 保存当前文档及切换会话的链路；保存失败停留在原文档。关闭/修改源码/卸载使旧异步结果失效，不修改已打开的正文。
- 源码最多 200000 字符、文件最多 1 MiB；转换前限制 AST 深度与节点数，转换后执行现有 validateDocument。单公式沿用 2000 字符和全文公式 100000 字符边界；不可用的单公式按带分隔符文字保留并说明，累计超容量拒绝导入。
- 导入支持标题、段落、加粗、斜体、删除线、行内代码、链接、列表、引用、分隔线、代码块、GFM 普通表格和美元分隔公式。H4–H6 降为 H3；任务项保留勾选文字；脚注保留编号与正文；HTML 源码显示为文字；图片保留替代说明和地址，不执行脚本、不联网取图片。引用式链接先解引用，所有链接经过现有协议检查，不能作为链接的地址保留为文字。
- 导出只读取捕获的不可变快照，生成 .md 源码及转换说明。字体、颜色、行距、缩进、纸张和分页无法用常规 Markdown 表达；图片输出文字占位；合并单元格、侧表头或富单元格表格按行保留块内容并报告。普通首行表头表格使用 GFM，源码围栏、文字转义和标记相邻关系由序列化层处理。
- 导出弹窗展示实际待下载源码和本次降级说明，下载不依赖当前浏览器保存成功。原快照不变；等待模块加载时退出会话不再显示弹窗或触发下载。取消不写文档，错误收口 pending 并允许重试。
- 不改变文件 schema、编辑器正文所有权、撤销或本地资源存储。不增加后端、网络图片导入、附件或自动把编辑区输入转换成 Markdown。

依赖与契约依据：[unified](https://github.com/unifiedjs/unified#compatibility)、[remark-parse](https://github.com/remarkjs/remark/tree/main/packages/remark-parse)、[remark-stringify](https://github.com/remarkjs/remark/tree/main/packages/remark-stringify)、[remark-gfm](https://github.com/remarkjs/remark-gfm)、[remark-math](https://github.com/remarkjs/remark-math/tree/main/packages/remark-math)。选定主版本兼容 Node 16+，均使用 MIT 许可；安装、测试与构建在 Node 18.18 上验证。

## 结果与验证

2026-09-08 完成 Markdown 导入、导出。入口为顶部「导入 Markdown」和「导出 → Markdown 文档」。弹窗使用 AntD 5 的 Modal、Form、Input、Button 和 Alert；操作按钮固定在正文滚动区外，较长的转换说明不会遮住操作入口。

导入支持读取 UTF-8 文件和粘贴源码。预览同时显示实际转换说明与前 5000 字符的纯文本；确认后通过既有保存、会话切换流程生成新文档。导出预览展示待下载 Markdown，超过 200000 字符时只截取界面预览，下载仍包含全文，并提醒超出本轮重新导入范围。

| 内容 | 转换行为 |
| --- | --- |
| H1–H3、段落、常用文字标记、链接、列表、引用、分隔线 | 映射为既有节点；链接通过现有协议校验 |
| 围栏代码、行内代码、行内及独立公式 | 保留源码；代码附加参数等不支持信息给出说明 |
| 普通首行表头表格 | 使用 GFM，支持按列对齐；导入列数不齐时补空格并保留已有单元格 |
| 合并表格、特殊表头、富单元格或无法安全序列化的单元格 | 导出按行、格保留正文和块内容，附转换说明 |
| H4–H6、任务列表、脚注 | 分别降为 H3、勾选文字、带编号正文并说明 |
| HTML、图片 | HTML 保留为文字；导入保留图片说明和地址，导出本地图片保留说明，不读取或下载图片 |
| 字体、颜色、下划线、缩进、纸张、分页及复杂排版 | 显示本次实际发生的转换说明；分页符保留文字提示 |

边界处理补充：AST 最多 48 层、50000 个节点；矩形化后的单张表格最多 10000 个单元格，先检查容量再补齐。重复引用定义采用第一个定义；空引用地址不会变成 `undefined`。有序列表导出使用固定编号标记，合法九位起点可以保留；超过九位会从 1 编号并报告原起点。加粗与斜体使用不同分隔符，连续文字标记先合并，避免相邻分隔符改变重读结果。删除线边缘空白移出标记并说明。

普通文字中的换行转为显式换行，文字标记只保留在各行正文；硬换行自身的标记移除并说明。段首、段中连续换行可以保留，Markdown 无法表达的段尾硬换行移除并报告，纯换行段随空段落折叠。标题含正文换行时降为段落并报告原级别，行内代码换行按 Markdown 规则转为空格。最终审查发现的带格式硬换行、连续空行导致标记泄漏问题已修复，补上实际导出→导入回归。

### 风格与契约审计

本批新增和修改的 Markdown 代码范围内，qucm-code-style 与 frontend-code-style 裁定为符合，未保留已确认偏差。沿用 React 17、JavaScript / JSX、Zustand、AntD 5 和 Rsbuild；没有 TypeScript、TSX 或新增全局状态。函数长度 AST 检查均不超过 80 行，最长为浏览器验收入口 79 行。组件命名导出、私有组件后置，事件处理在 effect 前，卸载清理只使异步结果失效，样式采用 CSS Modules。

输入文件与文本在边界检查，解析树在映射前检查，生成模型在交给编辑器前执行现有 schema 校验。导入弹窗拥有临时状态，FileActions 拥有保存和会话切换，Tiptap 继续拥有正文。导出读取捕获的快照；映射只生成新树，没有回写源文档或增加撤销步骤。

### 原理核对

1. **为什么直接转换 AST？** Markdown 的嵌套、围栏和转义由 unified / remark 解析与序列化；映射层只处理有限的节点契约。避免经 HTML 丢失代码语言、公式源码，也避免把 HTML 标签作为可执行页面内容引入。
2. **关闭弹窗后，迟到的文件读取为什么不会覆盖新输入？** 每次读取、修改、取消或卸载推进版本号，异步返回只接受当前版本。预览状态不进入正文；保存和切换期间由父级禁用关闭与重复操作，保存失败保留当前会话及可重试的转换结果。
3. **为什么表格要先检查补齐容量？** 原始 AST 的节点数不等于矩形化后的单元格数。先计算最大列数乘行数，再分配补齐单元格，可以阻止稀疏表格膨胀；多出的原始内容也不会被按首行列数截断。
4. **为什么同一段文字还要合并标记并调整序列化选项？** JSON 文本片段可能共享外层标记，相邻分隔符会产生歧义。先合并相同包装，加粗用星号、斜体用下划线，再以真实解析器验证重读；列表固定编号则避免九位起点递增成十位标记而脱离列表。
5. **为什么不能承诺 Markdown 完整往返？** 编辑器包含 Markdown 无法表达的样式、图片资源、合并表格和分页。转换器逐项给出本次说明并保留可读内容，完整可编辑备份依然使用 Mewoc 文件。
6. **为什么只读也允许导出？** 导出只读不可变快照，不修改编辑器、资源或撤销历史。对待下载源码的预览和实际 Blob 使用同一个结果，生成期间退出会话会丢弃迟到结果。
7. **为什么不能把文字标记直接包在换行外？** Markdown 分隔符对空白和段落边界有规则，直接包裹硬换行或连续空行会让分隔符成为正文。换行先独立，标记仅包裹各行文字；不能表达的段尾换行明确说明，避免把反斜杠或字符实体混入正文。
