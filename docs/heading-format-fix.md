# 标题格式刷与字号回显修复

2026-09-08：标题默认字号来自 CSS，原格式刷只读取 textStyle 属性；字号控件在没有显式值时固定显示 12pt。因此默认标题刷到正文没有复制字号，光标位于标题时控件也显示错误。本次已复现并修复两处。

## 行为与契约

| 内容 | 本次行为 |
| --- | --- |
| 格式来源 | 由 Tiptap 节点与 marks 提供显式格式；缺省的字号、颜色、字重和行距读取当前段落的实际 CSS，格式刷及字号/颜色/行距控件共享读取逻辑 |
| 字号单位 | 保留 H1 / H2 / H3 的 30 / 20 / 17px 外观，对应显示并保存为 22.5 / 15 / 12.75pt，加入允许的字号列表；不将像素数直接当作 pt |
| 手动修改 | 显式字号优先；光标、混合选区、空标题、切换标题级别和清除文字格式后重新计算回显 |
| 格式刷 | 复制默认标题的字号、颜色、字重和行距；反向从正文刷到标题也覆盖这些外观属性，目标段落类型、标题级别、链接与结构仍保留 |
| 保存与复制 | textStyle 增加受白名单约束的 fontWeight，行距加入标题现有 1.55；内部复制、Mewoc 和 HTML 保留这些值。正文中的字重不是第二份 React 状态 |
| 加粗操作 | 工具栏与快捷键能够改变格式刷带来的显式字重；只读及组合输入期间拒绝新的字重命令 |
| 生命周期 | 格式刷沿用现有单次/连续模式、选区监听与取消清理；生效格式读取是同步派生值，不新增监听、异步任务或全局状态 |

字重修复包含一个真实浏览器中发现的复制边界：Tiptap 重新解析 `font-weight: 600` 时可能同时产生 strong，TextStyle 又位于 strong 外层，浏览器的 bolder 规则会进一步增粗。输出使用 data-font-weight 标识显式字重，并让其内部 strong 继承该值。该规则与正文样式一起进入静态 HTML 和打印输出，保留原字重；没有显式字重的普通加粗继续沿用原行为。

仍按已有格式刷范围复制，未扩展到标题层级、段前段后间距、字间距、列表类型、图片或代码等结构。文件协议尚未发布，本次保持 schemaVersion / formatVersion 为 1；新程序可以读取旧文件，旧程序的严格校验可能拒绝新增字号、行距或 fontWeight 字段，不宣称双向兼容。

## 风格与原理核对

本次新增及修改范围符合 qucm-code-style 与 frontend-code-style，未保留确认偏差。保持 React 17、JavaScript / JSX、Tiptap、AntD 5 及既有状态所有权；局域网 UUID 修复等已有工作区改动保留。

1. **为什么不能只补一个标题字号映射？** 格式刷和控件需要一致的来源；读取实际段落 CSS 可以同时处理字号、颜色、字重和行距，并优先保留用户显式设置。
2. **为什么 30px 显示为 22.5？** 控件单位为 pt，1pt 等于 96/72px；通过 CSS 计算样式读取，不使用受纸张缩放影响的屏幕尺寸。
3. **为什么标题刷到正文后仍是正文？** 标题级别属于内容结构，本次将外观保存为文字和段落格式，不改变目标的大纲语义。
4. **为什么要处理嵌套 strong？** 字重和加粗标记可以同时存在，浏览器默认 bolder 会叠加效果；显式字重范围内继承原值，才能保证复制与导出往返的实际外观一致。
