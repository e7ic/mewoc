# M6 第一批：格式刷

## 实施前白盒模型

按首期方案第 10 节的后续顺序，先交付格式刷。M5 已由用户明确暂缓；本轮必要验证只针对新功能，不恢复 M5 人工验收。沿用 React 17、AntD 5、Tiptap 3、Zustand、Rsbuild 与两套代码风格。

- 格式快照和单次/连续模式由当前编辑器的 ProseMirror 插件持有；工具栏只订阅该状态，不在 Zustand 再存第二份。新会话天然为空。
- 从选区第一个可格式化文字读取来源；光标位于普通段落/标题时可读取当前文字样式。复制粗体、斜体、下划线、删除线、字体、字号、前景/背景色，以及段落对齐和行距。混合来源按第一个文字取值。
- 应用只修改目标选区中的段落/标题文字与所在段落样式。保留链接、正文、图片、表格、标题级别及列表结构，不复制来源链接或代码样式。
- 点击格式刷进入单次模式，连续按钮进入连续模式；再点当前模式或按 Esc 取消。鼠标结束选择或键盘完成选择后应用；空光标、节点选区和代码块不消耗模式。工具栏也提供明确“应用”按钮供键盘操作。
- 应用整批标记与段落属性属于一个事务；在历史前后设分组边界，单次撤销可以恢复目标原样，不吞掉前后输入。
- 选择结束后延迟到下一帧，以等待浏览器与 ProseMirror 同步选区。回调核对当前文档、插件状态、可编辑与组合输入状态；失焦和销毁取消帧。普通正文编辑、组合输入开始、只读或文档切换终止格式刷。
- 复用既有 schema 属性，文件版本和存储结构不变，格式快照不落盘。无后端请求与运行依赖变化。

扩展 API 依据 [Tiptap 官方文档](https://tiptap.dev/docs/editor/extensions/custom-extensions/create-new/extension)；插件 state、DOM handler、appendTransaction 和 closeHistory 以已安装的 ProseMirror 源码契约核对。

## 结果

2026-09-07：已实现并验证本批格式刷。

- 「开始」工具栏新增 AntD 格式刷、连续模式、应用与取消按钮。普通单次应用后退出，连续模式保留；支持 Esc 和再次点击当前模式取消。
- 鼠标左键结束选区、松开 Shift 或全选快捷键结束时尝试应用，也可点击「应用格式」。按住 Shift 连续扩选不会提前应用。节点选区、表格单元格选区、空光标和纯代码内容不消耗模式；表格内普通文字选区可以应用。
- 只改实际不同的标记/段落属性，相同格式不产生空撤销项和重复保存。启用或取消只改变插件元数据，不标脏；文字格式一次变更对应一次保存更新。
- 普通输入、组合输入开始、只读切换和文档会话结束终止模式。失焦取消待执行帧，但保留来源，便于返回后继续选择目标。
- 混合来源取首个合适文字；整段属性作用于目标文字所在段落，未选中文字的行内样式不变。不会改变标题级别、列表层级、链接地址、表格尺寸或图片。

## 风格与契约审计

审查范围为本轮新增格式刷扩展、工具栏组件、必需调用链和测试；确认风格偏差为零，符合 `$qucm-code-style`，并执行 `$frontend-code-style` 的白盒规则。

沿用同模块具名组件、两空格、双引号、无分号、私有扩展目录和现有 Sass 样式。工具栏订阅当前编辑器插件状态；临时快照不进入 Zustand 或持久化。React 17、AntD 5、Zustand 与 Rsbuild 以用户明确选择为准。此次没有请求层或权限契约。

本轮审计修正了两点：Shift 扩选需要等待松键；同格式反复应用应跳过相同标记和段落属性，避免无意义历史和保存。延迟回调通过文档/来源身份检查拒绝过期操作，并在失焦和销毁时取消；没有新增全局监听或后台任务。

## 原理问题与解释

1. 为什么格式快照放在插件而非再放一份 Zustand？它跟随当前编辑器会话，事务是唯一变更入口，工具栏读取同一来源，不会在切文档时串用旧格式。
2. 为什么 `mouseup` 不能直接读选区并执行？浏览器与 ProseMirror 的选区同步可能尚未结束；下一帧读取最终选区，同时校验文档和来源身份，拒绝迟到操作。
3. 为什么不能在每次 Shift + 箭头松开箭头时就应用？用户可能还按着 Shift 扩大选区；提前执行会消耗单次模式，只刷最初的少量文字。
4. 为什么要在格式事务前后都设置历史边界？只设前边界会让随后的连续输入合并进同一撤销组；末尾附加不入历史的边界事务可将后续输入分开。
5. 为什么不先删除所有 marks 再重建？这会移除目标链接，还可能为相同格式制造空历史；只比较并修改样式白名单中的差异，既保留语义标记，也避免重复保存。
6. 为什么只取消动画帧仍不够？帧也可能已经进入执行阶段，所以回调还核对编辑器生存、可编辑状态、焦点、组合输入与文档身份。
