# M6 第三批：界面主题

## 实施前白盒模型

按已确认的后续顺序实现浅色、深色、跟随系统三档界面主题，默认跟随系统。M5 保持暂缓。本批按 `$qucm-code-style` 和 `$frontend-code-style` 实施。

- 应用级 Zustand 保存主题偏好、系统深色状态及偏好读写错误；有效主题由两者派生。文档 store、JSON、revision 和撤销历史不参与主题切换。
- 偏好使用 `mewoc.theme` localStorage 键，仅接受 light/dark/system。读取异常回退 system 并显示说明；写入失败仍应用本页选择，但提示未能保存，允许再次选择重试。
- 根主题 Provider 订阅一次 matchMedia 与 storage 事件，卸载时解绑；其他页面修改或清除偏好时同步，系统事件仅影响跟随系统的有效主题。静态消息/确认弹层订阅同一 store，不重复绑定浏览器事件。
- AntD 5 的 ConfigProvider 使用 defaultAlgorithm/darkAlgorithm；自有外壳使用一组带浅色默认值的 CSS 变量。根 data 属性控制颜色，主题 Provider 不加 key、不重建编辑器。
- 纸张与正文固定为浅色，内容 SCSS 保持静态值；HTML/打印生成不导入界面变量，避免主题进入文件或改变文字颜色。
- 控件放在「视图」页签，使用 AntD Select。主题属于用户界面偏好，只读状态仍可切换。
- 无后端和新依赖。测试覆盖存储异常、非法值、系统/跨页同步、监听清理，再通过浏览器验证外壳、浮层、文档与撤销保持。

实现依据 [AntD 5 主题文档](https://5x.ant.design/docs/react/customize-theme/) 和 [ConfigProvider 静态 holderRender](https://5x.ant.design/components/config-provider/)。

## 结果

2026-09-07 已完成。在「视图 → 界面主题」选择跟随系统、浅色或深色；只读时也能切换。偏好保存到当前访问源的 localStorage，新页面恢复，其他标签页同步。写入失败仍保留本页选择，控件旁显示错误，再选同一项可重试。

主题覆盖标题栏、工具栏、侧栏、工作区背景、状态栏和 AntD 控件/浮层。纸张固定浅色，正文和导出样式使用原来的固定颜色。主题不会写入文件，也不会改变文档 revision、已保存状态或撤销内容。

## 风格与契约审计

本轮改动及必要调用链确认偏差为零，符合 `$qucm-code-style`，同步执行 `$frontend-code-style` 的白盒规则。具名组件、页面私有目录、两空格、双引号、无分号与现有 CSS Modules 保持一致。新增 appearance.scss 仅承载应用主题变量，未裸覆盖 AntD 内部选择器；内容 SCSS 不依赖该文件。

主题是应用级偏好，采用独立 Zustand store，避免放进随文档切换销毁的正文 store。静态 holderRender 与根组件共享主题订阅，只有根组件绑定浏览器监听。ConfigProvider 始终使用同一组件结构，不用主题值作为 key。根 DOM 属性在 layout effect 设置并恢复，事件在 effect 中绑定并解绑。

## 原理问题与解释

1. 为什么偏好与有效主题要分开？“跟随系统”是用户选择，系统深色是外部状态；只存 dark/light 会丢失跟随意图，系统变化也无法正确更新。
2. 为什么主题不能放进文档 store？文档切换会创建新实例，界面偏好却应延续；把它当正文属性还可能触发自动保存或污染导出。
3. 为什么静态确认框需要独立主题 Provider？AntD 静态方法创建另一棵 React 树，不继承根上下文；holderRender 订阅同一 store 后，已打开的弹层也能更新。
4. 为什么 Provider 不能用 theme 值作 key？key 改变会卸载并重建子树，编辑器实例及撤销历史可能丢失；更新上下文配置即可切换颜色。
5. 为什么纸张颜色不使用界面变量？界面切深色不代表用户修改了文档；固定正文规则可以保持编辑、HTML 和打印的文档色彩语义。
6. 为什么保存失败仍应用本页选择？主题不涉及正文写入；保留即时反馈并明确标注偏好未落盘，再次选择可重试，避免把显示成功误说成保存成功。
