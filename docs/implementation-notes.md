## 规范裁定与仓库画像

本轮使用 qucm-code-style 的继承者模式及 frontend-code-style 的白盒/原理反问模式。开始时仓库仅有两份方案，无代码、API、路由、鉴权、lint、测试或 Git 配置。

用户明确的 React 17、JavaScript/JSX、Zustand、pnpm，以及已授权实施方案优先于技能样本中的 React 18、Redux、Router 和构建器版本。保留 Vite。按新指定的两套技能收敛目录为 src/pages/editor，局部样式使用 sass/*.module.scss，页面名称与文件名一致且以 Page 结尾。Ant Design 4 提供表单、弹窗和反馈，原生按钮用于定制编辑工具栏。样式主题集中定义。没有公司接口，不创建 EolAxios 占位实现、登录守卫或虚构 API。

## 编码前白盒模型

- 页面拥有本地文档加载/切换状态。切换前由当前会话保存最新内容，失败不切换；新文档用新的 key 重建会话。
- 编辑器实例拥有正文、选区、正文历史；按实例创建的 Zustand store 拥有标题、纸张、界面偏好和编辑 revision；局部表单拥有打开状态和临时值。
- 保存协调器拥有稳定计时器、进行中的 Promise、已保存 revision 和 IndexedDB storageVersion。写入成功只确认捕获的 revision；失败暴露明确状态，原内容不变。
- IndexedDB 在单个读写事务中比较 storageVersion，再写入文档与引用的 Blob。双标签页基于旧版本保存时返回冲突，禁止覆盖。
- 图片通过稳定 assetId 引用；Blob 与 object URL 在会话资源集合中。持久化只保存 ID/尺寸，导出时才编码图片。删除节点不即时删除 Blob，以支持撤销。
- 异步导入先完成文件与资源校验，再替换文档；取消、只读、卸载和迟到回调不得写新会话。计时器、DOM/编辑器事件、ResizeObserver、object URL 在所有者结束时释放。
- 读取、保存、导出和图片处理有独立 pending；错误不转换成空文档或成功。首期没有远端请求，宿主契约留在方案中，不添加空 service。
- 输入只触发文档 revision 和编辑器必要订阅；序列化在保存/导出时发生。纸张 zoom 与资源缩放使用各自坐标，图片尺寸在拖动完成时写入一次事务。

## 关键正确性复核

- `save-coordinator.js` 捕获待保存 revision；后台写入期间发生新编辑，不会把新版本标成已保存。完成后继续调度遗漏的新 revision；手动 flush 等待到当前版本。失败保留 storageVersion，便于确定性重试。
- `local-repository.js` 在同一 IndexedDB 事务内比较存储版本、写入正文和资源；图片数据库键包含文档 ID，两个导入文件即使复用相同 assetId 也不会互相覆盖。
- `FileActions.jsx` 切换前锁定编辑并等待保存，失败留在原会话。已保存文档在当前保存完成后重新读取；避免“打开自己”载入陈旧快照。EditorPage 用新 session key 重建会话。
- `use-selection-bookmark.js` 在事务中映射选区；链接弹窗和图片属性表单的确认操作不会继续使用过期裸 position。异步图片载入检查卸载、只读和目标删除。
- `document-image.js` 与 `table-column-resize.js` 将屏幕位移除以页面缩放，再提交文档尺寸；拖动预览不按每一帧写撤销记录。清理监听、观察器、计时器和 object URL 各有明确所有者。
- `use-editor-input.js` 清理粘贴 HTML 的脚本、事件和外链图片，保留允许的文字格式。回归发现 Tiptap HTML 解析会把未设置的文字样式写为 `""`；schema 已明确允许这些字段的空字符串，仍拒绝危险样式值。
- 正文只存在编辑器内；Zustand 存文档元数据与视图状态。工具栏选择订阅，大纲和字符统计按文档变化派生，不对每次光标移动重新序列化。

## 风格审查结论与裁定

本次新增源码及必要调用链确认的风格偏差为零，符合 qucm-code-style；frontend-code-style 的白盒、目录、命名、组件边界、AntD 表单和清理要求已执行。此结论限定本次静态审查与已验证契约，不替代下面的运行环境验收。

使用继承者模式：页面具名默认导出、复用组件具名导出、私有组件位于文件末尾；领域状态在最近所有者，跨组件端口由 Context 暴露；2 空格、const、无分号、双引号、CSS Modules 和集中主题。没有原项目可照搬的相邻代码。

用户明确的 Zustand、React 17 与已授权 Vite 方案优先于技能的 Redux / React 18 / 构建器样本；技能指定的 AntD 4 和 Sass Modules 用于实际表单与样式。Tiptap 节点视图和静态导出样式必须是共享全局规则，均限制在 `.mewoc-content` 范围。保留原生工具栏按钮以保持编辑选区和紧凑布局。没有引入 API、登录、路由占位层。

## 与实现绑定的原理问题

1. 保存 revision 8 期间输入到 9，为什么写入成功只能确认 8？`flush()` 如何确保切换前没有遗漏 9？
2. 为什么正文 JSON 不同步放进 Zustand？如果每次 selectionUpdate 都生成 JSON，会增加哪些成本？
3. 为什么删除图片后暂时保留 Blob？撤销、便携导出和会话销毁分别在什么时候需要或释放它？
4. 页面缩放到 50% 后，屏幕移动 20 px 为什么应该改变 40 px 文档宽度？表格和图片分别从哪里取得比例？
5. 为什么链接弹窗记录 bookmark 而不是固定 from/to？弹窗期间正文被修改或目标被删除时，两种做法有什么差别？
