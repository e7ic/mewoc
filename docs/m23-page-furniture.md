# M23 · 页眉、页脚与页码

## 使用与范围

两种工具栏模式的「页面 → 页眉页脚」均可设置：页眉、页脚独立开关，单行普通文字，左/中/右对齐，不显示页码、当前页码或当前页/总页数。设置草稿先预览，取消不改原稿，应用才进入文档页面元信息；页面设置不占正文的撤销步骤。

M23 完成时，编辑纸面是连续容器，页码为 `第 1 页`、`第 1 / … 页` 示意。后续 [M25 第一批](m25-pagination.md) 已接入按正文块实测的多页视图，编辑纸面逐页显示实际页码和总页数；历史、模板和小型页面预览继续使用示意。页眉页脚不进入正文、选区、复制、字数统计或批注；打印和 Word 仍各自计算物理页码。

文字最多 80 个 Unicode 码点，禁止多行和控制字符；启用的对应上/下边距至少 12 mm。全局共享字号预算按纸型、方向、左右边距和最长页码占位估算，自动选择 6–9pt、半磅步进；文字过宽时明确要求缩短或增加正文宽度。兼容合字的预算按展开字形保守计算，保存文字不做规范化。字体预算是估算，不承诺任意外部字体的精确宽度。

文档、Mewoc 备份、本地复制、历史版本和模板均保留完整设置；缺少新字段的旧文档不补写或迁移。独立预览读取各自的快照，修改当前文档不改变旧版本。

## 输出与往返

HTML 屏幕只显示纸面示意，打印使用一个全宽边距框和原生 `page` / `pages` 计数；同一侧其他两个框置空，正文不复制。文本用独立的 HTML 转义与 CSS 逐码点十六进制编码，不允许文字关闭 `style` 或执行活动内容。长正文的网页页脚位于容器末尾，打印时隐藏屏幕示意。

页面边距框从 Chrome 131 起支持。[Chrome 官方说明](https://developer.chrome.com/blog/print-margins)解释了真实逐页计数与边距框的行为。打印入口实际解析嵌套规则确认能力；不支持时停止该次打印并建议使用支持的 Chrome 或导出 Word。HTML 文件也带有打印兼容说明。请关闭系统打印的自动页眉和页脚，以免叠印。

Word 使用原生页眉/页脚，页码为 `PAGE` / `NUMPAGES` 域，并请求打开时更新；未重算查看器的初始缓存为 1，不能把该缓存当作最终页数。页眉与 M22 水印共用同一关系部件，保留原生水印。位置和字号与 HTML 使用相同的毫米边距和半磅预算。

导入只恢复经过完整验证的本项目 `MewocPageHeader_v1` / `MewocPageFooter_v1` 单段控件：实际节关系、完整结构、格式、普通文字及仅限页码的域均须匹配。识别先于普通域静态化，不绕过其他未知域和控件的校验。未知 VML 仍按旧规则拒绝；第三方普通页眉页脚继续按原语义转换，静态内容附在正文末尾。

自有格式往返只覆盖本项目规范导出的结构。Word/WPS 另存后若改写控件或域结构，文件可能被明确拒绝导回；应保留原 DOCX，本批未证明原生 Office 重存后的兼容性。

编辑器使用一份全局配置，首/偶页或分节的差异只按首节默认配置恢复并明确提示；仅首/偶页或后续节专用内容不会扩展为全文装饰。Word 整数 twip 令 12 mm 读回为 11.99 mm 时，仅已验证装饰的最小边距做量化修正并提示。源文件字节保持原样。

Markdown 和纯文本不携带页面装饰，转换说明明确提示；页眉页脚文字与示意页码不会伪装成正文输出。

本批不含富文本页眉、图片、分节编辑、首页不同、奇偶页不同、起始页码、自定义页码格式或实时自动分页。原始 Word 字体、分节和分页仍不承诺完整还原。
