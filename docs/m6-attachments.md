# M6 第七批：附件

## 实施前契约

沿用 React 17、JavaScript / JSX、Tiptap 3、Zustand、AntD 5、Rsbuild 1 和 Node 18.18+。M5 保持暂缓。本批没有新增运行依赖或服务端接口。

| 边界 | 当前证据与本批决定 |
| --- | --- |
| 正文与资源 | Tiptap 拥有正文及撤销；新增块级原子节点 `attachment`，只保存 `assetId`。文件名、MIME 和字节数继续由会话资源 Map / 文档 assets 清单拥有 |
| 文件兼容 | `schemaVersion: 1` / `formatVersion: 1` 保持现有未发布协议。旧图片不带 kind，继续按图片读取；附件显式使用 `kind: "attachment"`。新程序读取旧文件，旧程序会拒绝附件文件，不宣称双向兼容 |
| 文件输入 | 「插入 → 附件」每次选择一个本地文件，按不透明字节保存，支持空文件；单个最多 5 MiB，与图片合计最多 20 MiB。文件名最多 255 字符，缺少 MIME 使用 application/octet-stream |
| 读取状态 | 专用 hook 拥有附件读取状态与选区 bookmark；图片和附件共享会话任务锁。读取后重新检查当前资源容量；目标被删除、进入只读、切换会话或卸载后丢弃结果并清理监听 |
| 成功与失败 | 文件读取和校验完成后一次插入，插入、删除各自可独立撤销；失败不发布资源，不修改正文，恢复读取状态并显示原因 |
| 本地保存 | 沿用文档与 Blob 同事务写入、版本冲突检查和旧资源回收；删除后会话保留 Blob 与 URL 供撤销，退出会话统一释放 URL |
| 下载与输出 | 正文卡片显示文件名、大小、下载入口；只读仍可下载。下载地址统一按 application/octet-stream 生成，文件内容不进入预览或脚本执行。Mewoc 保留附件原始字节和 MIME；HTML 内嵌下载数据，打印仅显示文件说明；Markdown / 纯文本保留附件说明，Markdown 显示转换提示 |
| 粘贴 | 仅允许当前会话已有附件的稳定资源引用；跨文档或缺失附件按文字说明粘贴，不接收外部下载地址 |

## 验收目标

插入附件 → 保存刷新 → 导出 Mewoc → 新会话导入 → 下载，原始文件字节一致。覆盖混合图片与附件、空文件、容量限制、元数据与引用校验、独立撤销、删除后的磁盘回收及撤销恢复、只读、异步取消、HTML / Markdown 输出和内部复制。

## 实施结果

2026-09-08 完成本批。入口为「插入 → 附件」；选择单个本地文件后显示文件名、大小和下载入口。卡片可选中删除，只读保留下载入口。状态由 `useDocumentAttachments` 拥有；保存、导入与会话切换继续使用原来的流程。

附件与图片通过资源种类隔离，图片节点不能引用附件，附件也不能伪装为图片绕过图片字节校验。文件名与 MIME 不进入正文属性；显示使用 DOM 文本，下载名处理操作系统不支持的字符，实际 Blob 保留原 MIME。附件下载 URL 和 HTML 内嵌下载统一使用 `application/octet-stream`，不在编辑器中解释文件内容。

导出先获取当前文档快照，仅编码正文仍引用的唯一资源；验证 Blob 的类型和长度，旧图片继续校验文件签名。导入先检查 base64 长度、字符和填充，再解码，支持空附件和恰好 5 MiB 的边界。图片与附件共同计算容量，同一资源复制多次只计算一次；撤销历史保留的、已无正文引用的资源不计入当前文档容量。

## 风格与契约审计

本批新增及修改范围符合 qucm-code-style 与 frontend-code-style，未保留已确认偏差。沿用 React 17、JavaScript / JSX、Zustand、AntD 5 和 Rsbuild，未增加运行依赖或全局状态。组件与私有辅助函数分开，事件处理位于 effect 前；会话 Map 拥有 Blob，Tiptap 拥有正文和撤销，Zustand 只保存界面及文档状态。附件内容样式继续写入既有 `.mewoc-content` 命名空间，供正文、静态 HTML 和打印共用。AST 函数长度检查全部不超过 80 行，最长为浏览器验收入口 80 行。

## 原理核对

1. **为什么节点只存 assetId？** 正文引用稳定身份，文件名、MIME、字节数和 Blob 由资源层统一拥有，避免复制、保存和导出时出现两份互相矛盾的元数据。
2. **为什么读取前后都检查容量？** 文件读取期间正文可变化，例如撤销恢复旧资源。图片与附件共用任务锁，完成后按当前引用重新计数，才能确保真正插入时仍满足 20 MiB 限制。
3. **为什么只读或切换后仍要丢弃迟到结果？** 异步读取不能在用户已经离开目标后修改正文。bookmark 随事务映射；目标删除、只读或切换会永久取消当前读取，卸载立即移除监听。
4. **删除后为什么不立刻释放会话 Blob？** 撤销需要原字节。保存事务回收磁盘中已无引用的资源，会话仍保留它供撤销；撤销后保存可以重新写入，退出会话统一释放 URL。
5. **为什么下载使用二进制 MIME？** 附件可能是 HTML 或 SVG，编辑器只提供原文件下载。下载 URL 以不透明字节提供，Mewoc 中仍保存原始 MIME，显示文件名时按文本转义。
6. **为什么 Markdown 不带附件内容？** 当前 Markdown 交换流程不管理附件目录。导出保留文件说明并报告转换，完整资源备份由 Mewoc 承担；HTML 则将下载数据内嵌到单文件中。
