## 验收前白盒模型

本次继续补验图片与输入事件：图片节点视图拥有一次拖动的 pointerId、起始尺寸和文档引用，移动只更新 DOM 预览；仅同一指针正常释放且仍可编辑时提交尺寸。失焦、取消、失去捕获、正文变化与卸载均恢复已提交尺寸并释放监听。快捷键验收区分普通按键与组合输入事件；合成事件不作为真实中文候选确认的证据。

查找面板的输入值属于面板本地 state；重新打开时为空。已安装 Tiptap 3.31.3 的 clearSearch 只清 searchTerm，所以面板卸载还必须复位 replaceTerm / caseSensitive，使新面板的显示与实际替换契约一致。该复位只改搜索元数据，不创建正文编辑或保存 revision。

图片事件依据 [Pointer Events 的指针捕获与取消约定](https://www.w3.org/TR/pointerevents3/#pointer-capture)：按 pointerId 识别当前交互，正常完成与取消分开收口。窗口失焦和文档变化时取消预览是本编辑器的产品约束，不把未完成的拖动写入正文。

- 使用独立端口 4179，与用户当前 4177 的 IndexedDB 和打开偏好隔离。验收页点击运行后才挂载测试编辑器；正常完成后仅清理本轮创建的文档与资源。
- 常规功能复用已有浏览器用例，压力场景分别建立 10 万字、20 张图片、100×10 表格，不把三者的组合当成已支持容量。计时分别记录载入、布局、命令、序列化与存储；合成命令耗时不当作真实输入法延迟。
- 保存仍由 revision / storageVersion 两层版本管理；失败注入只发生在测试环境。验证原子写入、失败后导出、切换前 flush 与迟到回调。
- 打印 iframe 属于 ExportActions 的一次操作。资源等待中取消或组件卸载也必须释放 iframe，并禁止迟到 print；资源就绪才能进入系统打印。
- 检查现有样式与节点视图的屏幕坐标换算、选区映射、监听器解绑。未能通过真实操作确认的项目保留待验收状态。

## 结果

### 持续使用与保存异常补验

- 存储资源以已提交文档的 `assets` 为准；当前会话 Map 另为撤销保留 Blob。下一次保存只清理该文档上个版本不再引用的数据库资源，不清理其他文档，也不提前释放会话 URL。
- 版本检查、旧资源删除、新资源写入与文档更新必须属于同一事务。同步写入异常和异步事务失败都拒绝保存；失败不能推进 storageVersion，重试仍基于原版本。
- 生命周期验收使用专用测试页面重复挂载、插图、保存和卸载真实 Provider / PaperCanvas，观测对象 URL、ResizeObserver 和编辑器销毁。计数归零仅证明这些资源路径收口，不等于完整堆内存无泄漏。
- 测试只删除自己生成 ID 的记录；故障注入只存在于 Node 测试，不占满用户磁盘，不修改生产存储 API。
- 拖动还需处理鼠标在窗口外释放、mouseup 未送达的路径：后续 mousemove 的 buttons 已为 0 时，恢复预览并结束监听，不能继续用悬停坐标改列宽。正常拖动仍只在 mouseup 提交一次事务。

事务收口依据 [IndexedDB 事务中止算法](https://www.w3.org/TR/IndexedDB/#abort-transaction)：失败时回滚同一事务内的变更；测试分别注入同步 QuotaExceededError 与异步重复主键错误。编辑器延迟销毁依据已安装的 Tiptap React 3.31.3 `useEditor.ts` 的 `scheduleDestroy`，验收等待其自身定时销毁，不手工调用 destroy 掩盖清理问题。

环境：macOS 26.5.1、Google Chrome 152.0.7977.82、Safari 26.5、Node.js 24.13.1。版本从已安装应用及当前运行时读取。测试服务为 127.0.0.1:4179，用户预览保留 4177。

## 已定位并修复

1. **批量插图中断**：原异步监听把自己插入图片产生的选区替换认作“用户删除目标”，20 张只插入 1 张。现在只映射外部编辑事务，自己的插入结束后重新取得 bookmark。20 张图的解码、存储恢复、便携文件与 HTML 输出在 Chrome / Safari 均通过。
2. **Safari 列宽跳变**：`col.getBoundingClientRect()` 返回零宽；50% 场景实测从约 213 px 错误变成 40 px。改为读取真实单元格边界；所有行都合并的内部边界按已有列宽比例分配。普通列和整行合并列的拖动、撤销在两个浏览器通过。
3. **打印等待期间卸载**：原来 Promise 完成前没有可用的清理句柄，切换文档后旧资源可能继续触发 print。ExportActions 现在拥有 AbortController，卸载立即取消等待并清理 iframe，迟到资源不再打印。新增两个生命周期回归用例。
4. **保存失败图标与文案**：失败不再显示绿色成功勾；待保存使用时钟，失败使用红色错误图标。冲突提示明确“先导出当前副本，再刷新页面”，避免引导用户走必须先成功保存的切换流程。
5. **验收页与运行时**：点击运行后才挂载测试编辑器，减少热重载/仅打开页面留下测试文档；异常也进入清理流程。修复 Node 24 自带只读 navigator getter 导致 DOM 测试初始化失败的问题。
6. **删图后数据库资源积累**：旧实现仅写入当前图片，未删除上个已保存版本不再引用的 Blob。现在在版本校验后、同一事务内删除旧引用；会话 Map 保留以支持撤销。失败会回滚删除，不影响其他文档的同名资源。此变更阻止后续积累，没有扫描或迁移旧版本已经产生的孤立资源。
7. **鼠标释放事件丢失后继续拖列宽**：新增用例在没有 mouseup 时发送 buttons=0 的移动，修复前稳定失败；现在取消预览和监听，不写入悬停坐标。最初一次跨应用交替操作出现 50% 宽度变成 35 px，未记录当时完整事件，不能断言与此用例原因完全相同；随后独立真实拖动和明确边界回归均通过，保留跨窗口人工复核。
8. **图片缩放的取消与多指针边界**：修复前右键、其他 pointerId、失焦、正文变化会错误提交尺寸，只读时会残留临时预览；5 项用例稳定失败。现在仅接收左键发起的单一 pointerId；失焦、系统取消、失去捕获、正文变化、只读结束与卸载均恢复已提交尺寸，清理临时监听和捕获。正常释放先结束旧拖动，再提交尺寸，避免自己的文档事务被认作外部取消。6 个边界用例在两个浏览器均通过。
9. **重新打开查找沿用旧替换词**：原来面板本地输入清空，插件却保留 replaceTerm 和 caseSensitive，显示与操作契约不一致。回归用例先复现失败；现在卸载时一起复位插件元数据，不改变正文 revision。真实空替换和撤销已验证。
