# M7 · 旧式文本框和内嵌图片导入

后续：[实际报告导入修复](m7-docx-report-content.md)已使用用户提供的原文件补齐目录、页码、页眉页脚及图表数据转换。下文保留本批验收时的范围与结果。

日期：2026-09-12。用户反馈“文档包含暂不支持的旧式图形或文本框，请保留原 DOCX”。旧入口遇到任意 `w:pict` 或 `w:txbxContent` 就拒绝，连能提取正文的文本框也不能使用。本次按已验证结构展开文字和图片，原始输入文件不被修改。

## 转换范围

- VML 文本框中的段落、格式、列表、表格、公式和嵌套文本框按源 XML 顺序展开，放在所属锚点段落之后。单元格内的文本框仍留在单元格中。
- `mc:AlternateContent` 只选择一次非空 Fallback，并递归处理其中的兼容内容，避免现代表示与旧式表示导致文字重复或段落编号错位。
- VML `imagedata` 的内嵌关系进入现有图片校验、去重及资源清理流程；PNG/JPEG/WebP 范围不变。测试核对图片原始字节及再次导出后的字节。
- 预览明确提示：浮动位置、环绕、边框、背景和图形外观不保留。锚点所在段落的前后文字先组成正文，再接文本框内容，不承诺原页面空间阅读顺序。
- 纯矢量图形、艺术字、无兼容表示的对象、未识别的现代文本框、缺失资源与外链仍明确拒绝。提示可将文字移到正文，或在 Word 中把图形转为图片后重试。
- 修订、嵌入对象、脚注等原有拒绝边界保留；页眉页脚即使只有旧式图片也不能被静默忽略。图形的冗余 `o:gfxdata` 不解析、不执行、不保留。

实现：[docx-import-drawings.js](../src/pages/editor/tools/docx-import-drawings.js)。归一化在读取公式和段落编号之前执行，避免嵌套段落重复计数或错配。
