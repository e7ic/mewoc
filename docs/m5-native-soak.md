## 执行前模型

2026-09-07，继续使用 React 17 / Tiptap 3 / AntD 5 / Rsbuild / Zustand / JS/JSX。按 qucm-code-style 与 frontend-code-style 执行，仅增强开发验收入口；生产编辑器遇到可复现问题时才修复。

- 真实输入法验收需要系统候选窗口，以及浏览器 compositionstart/update/end、beforeinput/input 的 isTrusted 记录。粘贴中文、调用编辑器命令和合成 composition 不作为通过证据。
- 跨窗口指针记录 pointerdown/up/cancel、捕获/失去捕获、blur/focus 与 buttons；对比拖前、返回窗口后的尺寸及保存结果。不把单窗口完整 drag 当作跨窗口释放。
- 持续运行复用现有真实会话循环，计划 180 轮，每轮间隔 5 秒，约 15 分钟、360 次挂载。记录时间、JS 堆样本和现有资源计数；样本只保存数字，不保存 editor/DOM/Blob 引用。结果数组最多 180 项，诊断自身开销需计入。
- 页面拥有运行状态和结果；取消标记属于 ref。停止或卸载后完成当前会话清理，再退出循环；不得中止一半的数据库写入或强行销毁编辑器掩盖泄漏。窗口异常监听在 finally 移除。
- performance.memory 是 Chromium 的非标准估算，不能代表整个进程/图片解码内存，也不能以单次上涨判定泄漏。结合浏览器内存面板与自然回收后的低位观测；没有数据时记录 null，不填 0。
- Edge 当前未安装，先准备官方分发来源与可运行环境。测试只访问本地专用端口，不导入用户浏览器数据。
- 没有后端请求变化。测试继续只清理自己创建的文档 ID，不清空 4177 用户数据库。开发入口不进入生产构建。

### 持续运行与内存采样

Chrome 152.0.7977.82 在 4179 专用页面完成 **180/180 轮、360 次会话挂载**；末轮样本距开始 **914 秒**，之后等待末次 5 秒间隔并显示“结束：180/180”。

- 每轮对象 URL、ResizeObserver、指定 window 监听均归零，旧编辑器销毁断言通过，无被捕获的 window error。
- 累计创建 540 个对象 URL，单次在用峰值 1，观察器峰值 2。
- JS 堆样本：首轮 33.25 MiB、末轮 31.57 MiB，最小 29.09 MiB、最大 41.38 MiB；首分钟低位 30.03 MiB、末分钟低位 29.85 MiB。该次采样未出现持续增长。
- [完整 180 个时间/堆采样值与资源汇总](m5-soak-samples.json) 来自验收页 DOM 输出；记录单位为秒和字节。页面显示完成状态后提取，非估计补齐。
- 停止分支另行实际点击“停止并清理”，结束于 3/180，三轮均通过且资源归零；后续读取仍为 3 轮。停止完成当前轮，最迟等当前 5 秒间隔结束退出，不强行中断数据库操作。

验收限制：每轮仅一个 480×240 生成图片和 3×3 表格；资源观测限定在现有包装器覆盖的 URL、观察器和四类 window 事件。180 项诊断结果本身也占内存。没有采集堆快照的保留路径或强制 GC 对比，没有测图片解码/native 进程内存，也没有小时级运行证据。因此这次关闭的是“15 分钟持续切换与指定资源释放”子项，完整长期内存门槛仍保留。

该解释遵循 [MDN 对 performance.memory 非标准估算及适用限制的说明](https://developer.mozilla.org/en-US/docs/Web/API/Performance/memory)；进一步定位增长需使用 [Chrome 内存诊断面板](https://developer.chrome.com/docs/devtools/memory-problems) 区分 JS 活对象与原生内存。

### 原生输入与跨窗口

输入法专用页面添加 compositionstart/update/end、beforeinput/input、keydown 的有界记录，仅监听正文。最初由工具输入的 `nihao` 只有普通 insertText，不计为 IME 证据。随后用户在 Edge 手动操作并导出，现已获得真实组合输入证据，详见下表。

用户已完成一次 Edge 跨窗口手动操作。返回时记录到可信 mousemove、buttons=0，页面已保存；但最初最近 40 条的记录被连续移动覆盖，未留下完整按下/释放边界，不能把本次操作直接记为完整通过。

随后修正诊断记录：连续且 buttons 相同的 mousemove 合并为最后位置，最多保留 120 条边界与移动记录；附带图片样式宽度、表格列样式和已提交 colwidth，均为 DOM 只读快照，不保留节点引用。增加“导出原生验收记录”，一并导出正文、指针、输入法记录和当前尺寸；下载 URL 延后一个定时任务释放。该改动仍限于开发入口。

导出按钮已通过 Edge 原生点击验证，生成 JSON。刷新恢复后的 [首次手动操作后尺寸基线](m5-edge-after-first-manual.json) 为图片 600 px，表格列 190 / 211 / 485 px；此文件只有更新记录器之后的事件，不充当此前拖动的完整证据。已请求用户在同一 Edge 页面补做两种跨窗口释放及真实拼音、中英文切换，再导出复核。

用户补做并导出了 [第一份原生记录](m5-edge-native-first.json) 与 [第二份原生记录](m5-edge-native-second.json)。用户确认执行所请求的跨窗口操作；记录器没有保存窗口外框坐标，跨窗口动作来源为人工执行确认，页面事件用于核对释放与返回后的行为，不声称仅凭坐标自动判定鼠标已跨窗口。

| 场景 | 已读到的证据与裁定 |
| --- | --- |
| 图片释放 | 第一份记录索引 20–24：pointerdown → gotpointercapture → pointerup → lostpointercapture → buttons=0 的返回移动，均 trusted=true、pointerId=1；宽度由 600 变为 643 px，释放后移动保持 643 px |

本轮指针补验未观察到释放后悬停继续改变尺寸；合成的 blur、取消与丢失 mouseup 边界仍由既有自动化用例覆盖。未把这一次人工样例扩展成所有窗口、显示器、缩放组合均通过。

## 风格与验证

本轮新增/修改的开发验收代码及必要调用链确认风格偏差为零，符合 `$qucm-code-style`；同时按 `$frontend-code-style` 完成白盒审查。沿用现有验收页具名函数、React 本地 state/ref、无分号 JS/JSX 与直接诊断 DOM 的约定。原生诊断样式与按钮仅属于开发入口；不改变生产 UI、Zustand 状态所有权或运行依赖。用户指定的 React 17、AntD 5 与 Rsbuild 优先于技能中的默认版本。

`pnpm lint`、17/17 Node 测试和 `pnpm build` 均通过；生命周期组件 AST 函数长度检查通过。构建入口仅保留 index，输入法和指针记录不进入生产产物。本轮未修改生产编辑器逻辑。

原理复核问题：

1. 为什么可信 insertText 和粘贴中文都不足以证明真实 IME 组合输入成功？
2. 为什么循环取消使用 ref，而进度与结果使用 state？卸载后异步报告如何避免写入旧组件？
3. 为什么停止时应完成当前事务和清理，而不能直接销毁页面来取得“资源归零”？
4. 为什么每轮观察资源归零、JS 堆末值下降，仍不能证明完整进程没有泄漏？
5. 为什么跨窗口验收需要释放与返回移动的连续证据，而不能用单窗口 drag 或合成 blur 替代？
